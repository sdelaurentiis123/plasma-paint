# Finite-mark construction, 2026-09-05

The previous interface allowed whole-contour paths and full-field washes. The new opt-in `renderer.profile: stroke_only` permits only one paper initialization plus up to 1,100 finite `mark` operations. Each mark has 2–8 points, total normalized polyline length .002–.06, width .0005–.018, opacity 0–.8, pressure .05–1, texture 0–1, a medium, hex pigment and an integer field-sample anchor. All points must lie within .04 of that anchor. Paper grain is capped at .02. Existing legacy experiments are not silently changed.

Washes, full-contour primitives, blooms, arbitrary compositing and scatter operations fail this profile. Validation is performed on the host against the original supplied features after bounded sandbox execution. Generated code cannot disable the profile. These geometric limits are a construction constraint, NOT proof of scientific fidelity: color/intensity, coverage, temporal and structural rewards still require an audit before training.

Compact samples use the existing training-normalized signed density fluctuation (encoded 0–1 with zero at .5), stride three on the cached grid, excluding a two-cell display margin. Tangents use radial differences and periodic z differences, scaled to normalized display coordinates. They are visualization proxies, not physical flow. Samples are fixed in the grid across frames; no tracked-pigment advection is claimed. Invalid-cell frames are refused until an explicit spatial mask is available. Texture for each sample is seeded independently of frame number.

`finite_marks.js` is a reusable hand-authored renderer building tone with finite bristle strokes or pencil hatching. It does not paint contours or a raster background. The first sample-grid study was too visibly stamped; the delivered revision uses denser marks and density fluctuations. Mark assembly GIFs show marks accumulating within **fixed frame zero**, not plasma time. Other GIFs show actual frames 0–7 evolving.

Run `python3 -m scripts.render_finite_marks` for the permitted old-85604 training-cache preview in `artifacts/plasma_painter/finite-marks/`. Run `python3 -m pytest -q` for tests. The new `configs/plasma_painter/finite_marks.yaml` has a separate artifact root and enforces the profile in generation filtering and program rendering. Build/stage its permitted feature cache before sampling. The generation prompt and SFT prompt support the finite-mark contract. No new model sampling, fine-tuning, RL, or external API was launched for this change.

The Python renderer implements the new operation; browser runtime support and scientific/reward evaluation remain pending. Existing website galleries are unchanged. Do not advertise these previews as trained output or as browser-ready painters. Shot 85606 and upstream held-out data were not opened.
